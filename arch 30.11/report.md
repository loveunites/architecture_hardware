# Домашнее задание: Аппаратная виртуализация

## Задание 1. Проверка на своём железе

*   **Мой компьютер:** Windows 11, процессор Intel Core i7.
*   **Поддерживает ли виртуализацию:** Да. Это можно узнать по слову VT-x в характеристиках.
*   **Включена ли в BIOS:** Да, включена. (Если вдруг нет, нужно при включении ноутбука зайти в BIOS, найти настройки процессора и включить пункт Virtualization).
*   **Модуль KVM:** Это только для Linux, у меня Windows, поэтому пункт не подходит.

## Задание 2. Терминологический диктант

*   1 — C (EPT / NPT — помогает памяти работать быстрее внутри виртуалки)
*   2 — A (IOMMU — защищает устройства, чтобы они не мешали друг другу)
*   3 — B (VT-x / AMD-V — главный переключатель виртуализации в процессоре)
*   4 — E (virtio-blk — ускоренный виртуальный жесткий диск)
*   5 — D (virtio-balloon — забирает лишнюю память у виртуалки и отдает хосту)
*   6 — F (Overcommit — когда виртуалкам выдали больше ресурсов, чем есть на самом деле)

## Задание 3. Выбор архитектуры

*   **Ситуация A (Огромный сервер для облака):** **Тип 1.** Он ставится прямо на железо, без Windows посередине. Работает быстрее и тянет больше виртуалок.

*   **Ситуация B (Студент на ноутбуке):** **Тип 2.** Это обычная программа (как VirtualBox). Студенту нужно запускать ее прямо из своей Windows, не стирая систему.

*   **Ситуация C (Лаборатория без админа):** **Тип 2.** Программы типа VirtualBox просты в установке. Для сложных серверных систем (Тип 1) нужен специалист.

## Задание 4. Расчёт и рассуждение про overcommit

1.  **Цифры:** Всего просят 32 ядра (32 / 16 = 2.0 — переподписка по ядрам). Всего просят 144 ГБ памяти (144 / 128 = 1.125 — переподписка по памяти).
2.  **Почему процессор не жалко:** Программы не всегда грузят ядра на 100%. Процессор просто переключается между задачами так быстро, что все довольны.
3.  **Почему память опасна:** Если физической памяти не хватит, системе придется скидывать данные на диск. Это вызывает страшные тормоза. Чтобы спастись, гипервизор использует **«воздушный шарик» (balloon)** — забирает неиспользуемую память у одной виртуалки и отдает другой.
4.  **Что поменять:** Уменьшить память у ВМ-4 с 48 ГБ до 40 ГБ. Всем хватит, и риск зависания снизится.

## Задание 5. ВМ против контейнера

*   **Что виртуализуется?** ВМ: создает целый виртуальный компьютер с нуля. Контейнер: просто изолирует программу внутри одной ОС.
*   **Чьё ядро?** ВМ: своё собственное. Контейнер: общее (использует ядро хозяина).
*   **За счёт чего изоляция?** ВМ: за счет гипервизора (он как строгий начальник). Контейнер: за счет ограничений самой ОС.
*   **Что легче запустить 50 штук?** Контейнеры. Они почти не едят память и запускаются за секунды.
*   **Когда контейнер опасен?** Если хакер взломает общее ядро системы. Тогда он сразу получит доступ ко всем контейнерам на компьютере.

## Задание 6. Критика эксперимента

1.  **Неравные условия:** Студент дал виртуалке только 2 ядра из 8. Понятно, что она работала медленнее.
2.  **Плохая программа:** VirtualBox (Тип 2) сам по себе тормозит, потому что работает через Windows. Для честного теста нужен Тип 1.
3.  **Лишние программы:** На основном компьютере работали браузер и другие программы, которые ели ресурсы. А в виртуалке было пусто.
*   **Вывод:** Студент сравнивал не технологии, а разные условия. Его вывод «виртуализация плохая» — неправильный.
